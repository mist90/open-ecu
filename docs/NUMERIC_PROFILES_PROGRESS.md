# Числовые профили: первый рабочий этап

Актуальный этап: [native-тракт управления, ADC/PWM и стендовые сравнения](CONTROL_NUMERIC_BENCH.md).

Следующий этап выполнен: [float/fixed PI проверены на JK42BLS01](PI_NUMERIC_BENCH.md).
Ниже сохранены результаты исходного этапа; текущий профиль скорости использует
Q24 для непрерывных и Q28 для дискретных коэффициентов.

Ветка: `feature/numeric-profiles-pi`.

## Реализовано

Прошивка STM32G431 использует PI-only. Внешний PI работает на 100 Гц,
внутренний six-step PI, FOC, PLL и HallMonitor — на 20 кГц. Обе частоты задаются
в HAL-независимом заголовке порта `STM32G431/Core/Inc/ecu_config.hpp`;
настройка аппаратных таймеров использует те же значения.

`PiController<LoopTypes, SampleRateHz>` хранит предвычисленные `Ki / (2*f)`
и `Kb / f`, применяет трапецеидальное интегрирование, conditional integration
и back-calculation. FOC и PLL используют предвычисленное `Ki / f`.
Фаза PLL интегрируется делением скорости на частоту.

Скоростной регулятор и ограничитель ускорения продвигаются на один такт
за вызов; время стоянки не превращается в длинный шаг интегрирования при старте.
Предыдущая ошибка PI участвует в трапецеидальном интегрировании.

В HallMonitor длительности настройки заданы целыми микросекундами, а время
незаконного состояния — целыми тиками. Порог округляется вверх до полного такта.
При 20 кГц 300 мкс означают ровно 6 тиков; прежнее накопление float могло
сдвинуть срабатывание ещё на один такт. Затухание вычисляется при настройке.

`AT+SPID`, `AT+CPID`, `AT+FPID` и `AT+PLLID` требуют ровно два конечных числа.
Третий коэффициент, неполная пара, NaN/Inf и мусор после числа приводят к `ERROR`.
Настройки публикуются вместе с дискретными коэффициентами под CriticalSection.
Изменённые параметры скоростного PI сохраняются для своего электрического режима.

## Числовая основа

`FixedPointType<FractionBits, Storage>` имеет явные преобразования форматов,
округление к ближайшему с половинами от нуля и насыщение. Перехода в float
по неявному преобразованию нет. `multiplyTo<Out>()` сохраняет полный 64-битный
результат произведения двух 32-битных операндов до выбора выходного масштаба.
`divideByInteger<Out>()` позволяет делить непосредственно на целую частоту.

Деление ненулевого числа на ноль насыщает результат по знаку; `0/0` даёт ноль.
Отрицательные сдвиги представлены арифметикой без signed-shift UB. 64-битные
значения используются для накопления и преобразований; входы умножения имеют
хранение до 32 бит, чтобы не требовать 128-битного типа на ARM.

Начальные форматы fixed-профиля:

| Тип | Хранение | Дробные биты | Диапазон, верхняя граница исключена |
|---|---|---:|---|
| Current | int32 | 20 | [-2048, 2048) A |
| Voltage | int32 | 18 | [-8192, 8192) V |
| Angle | int32 | 24 | [-128, 128) rad / Hall steps |
| Speed | int32 | 16 | [-32768, 32768) |
| Duty, Fraction | int32 | 30 | [-2, 2), включая точную единицу |
| Gain | int32 | 16 | [-32768, 32768) |
| Speed PI step gain | int32 | 22 | [-512, 512) |
| Current PI step gain | int32 | 28 | [-8, 8) |
| PI accumulator | int64 | 32 | [-2^31, 2^31) |
| PI anti-windup error | int32 | 12 | [-524288, 524288) |

Это начальные форматы для проверки PI. Диапазоны остальных алгоритмов и
промежуточных результатов будут уточняться при сквозной параметризации.
Представление дискретного коэффициента задаёт дополнительное ограничение:
например, Current PI требует `abs(Ki / (2*f)) < 8` и `abs(Kb / f) < 8`.

### Исходное падение PLL

В `tests/test_motor_pll` проверка S1 требует на 0,1 с оценку скорости не ниже
половины реальной. До изменений получено 13,184703 при реальной скорости
40,040726; после перехода на частоту — 13,184695. Остальные три сценария проходят.
Это исходное расхождение с контрактом теста, требующее отдельного разбора;
порог проверки не ослаблялся.

Скрипт PLL теперь возвращает ошибку теста и запускает интерактивный график только
с `--plot`. Ранее отсутствие `set -e` позволяло скрыть падение последующим
успешным запуском графика.

Прошивка пока собирается с float: FOC, PLL, HallMonitor, ADC/PWM, настройки
двигателя и телеметрия требуют дальнейшей параметризации по основному плану.
Математические профили с LUT и полная fixed-point прошивка ещё предстоят.
Стендовая проверка и измерение ISR нового варианта также предстоят.
