# Native float / fixed-point тракт управления

Этап ветки `feature/numeric-profiles-pi`, 2026-10-14 (UTC+3).
Стенд: STM32G431, 170 МГц, JK42BLS01, около 20,8 В, без нагрузки.

## Что переключает профиль

`NUMERIC_PROFILE=float|fixed` выбирает представление в обоих периодических
контурах: ADC → HallMonitor/PLL → PI/FOC/six-step → PWM. Типизированы состояния
контроллера, фильтры, ограничитель ускорения, преобразование NTC/ручки газа и
упаковка OSC. В native-тракте нет промежуточного перехода в float.

Чистые ядра `MotorPLLCore<Profile, Hz>`, `HallMonitorCore<Profile, Hz>`,
`FocControlCore<Profile, Hz>`, `AdcConversionCore<Profile>` и структуры
`MotorAlgorithmInputT/OutputT`, `MotorStatusT` используют именованные типы.
Аппаратные фасады и `BldcController` пока выбирают их через `ActiveNumericProfile`.

Настройки двигателя, модельный расчёт PI, публичные совместимые методы и
текстовый AT-интерфейс ещё float-facing. Поэтому **весь ELF пока не является
прошивкой без float**: newlib float formatting/parsing ещё подключены.
`PiFloatInterface::updateNative()` обходит преобразования в периодическом пути;
проверяемая установка коэффициентов остаётся на границе конфигурации.

## Форматы

Qn здесь означает n дробных битов знакового int32; широкие состояния указаны отдельно.

| Величина | Формат |
|---|---|
| Ток | Q20, ±2048 А |
| Напряжение | Q18, ±8192 В |
| Запрос напряжения до ограничения | Q12, ±524288 В |
| Угол, радианы / Hall steps | Q24, ±128 |
| Механическая скорость | Q16, ±32768 об/с |
| Скорость PLL | Q14, ±131072 steps/s |
| Duty, доли, ADC scale, шунт, L, потокосцепление | Q30 |
| Коэффициенты скорости / тока / PLL | Q24 / Q16 / Q14 |
| Дискретные коэффициенты обычного PI / FOC / PLL | Q28 / Q24 / Q24 |
| Интеграторы PI/FOC, фаза PLL, ramp, Hall leakage | int64, 32 дробных бита |
| Интегратор PLL | int64, 24 дробных бита |
| Публичный Hall count / сырой ADC count / температура | Q16 / Q12 / Q16 |

Положительные границы диапазонов исключены. Преобразования и арифметика
насыщаются; округление — к ближайшему, половины от нуля. Нулевые смещения ADC
получаются из целых сумм. Настройки вне диапазона отклоняются до публикации;
ошибка настройки FOC теперь также препятствует `initialize()` контроллера.

Ramp хранит дробный остаток в int64: простое округление каждого приращения
до Q16 накапливало ошибку и было обнаружено существующим тестом ускорения.

## Математика и быстрый путь

- `FloatMath` хранит 256 float-точек синуса; `FixedMath` — 65 Q30-точек четверти
  периода (260 байт). Симметрия даёт 256 точек, между ними линейная интерполяция.
- Фаза LUT — целый оборот uint32; перевод радиан использует предвычисленный
  reciprocal. SVPWM вычисляет один reciprocal Vbus вместо трёх делений.
- Квадраты напряжений расширены до 64 бит. Целочисленный sqrt округляет внутрь:
  `Vd² + Vq² <= Vlimit²`. После реконструкции третьего шунта используется
  zero-sum Clarke без лишнего деления на три.
- Hall detector сравнивает перекрёстные произведения; отношение для диагностики
  вычисляется только при чтении снимка.
- NTC: нормализация положительного отношения, затем полином ряда atanh для ln.
  Граничные ADC-коды и отключённый датчик сохраняют прежнюю семантику sentinel.
- Модуль FOC-напряжения для `duty_cycle` считается по согласованному снимку
  в 100-Гц контуре. В OSC scalar duty для FOC удерживается между этими обновлениями;
  токи и угол OSC по-прежнему захватываются на 20 кГц.
- Release остаётся `-Os`, кроме двух крупных ядер PLL/FOC с локальным GCC `-O2`
  (`control_optimization.hpp`). Малые saturating операции принудительно inline.
  Debug остаётся `-O0`. Эти изменения потребовались для временного бюджета fixed FOC.

## Host и ARM

Все следующие проверки проходят:

- арифметика/PI: 1092 проверки с UBSan; дифференциальные PI-трассы;
- FOC: по **212 проверок** на профиль, включая MOTOR_1 model, оба направления,
  decoupling, повреждённый худший шунт, насыщение и восстановление за **2,70 мс**;
- PLL: 10/20/40 кГц, обе стороны и reacquisition после чрезмерного ускорения.
  В номинальных трассах максимальная разность угла <0,0002 step, скорости <0,029 step/s;
- LUT: максимальная ошибка sin/cos **0,0000754**; обратное преобразование 18-А
  вектора — **0,002713 А**; отличие SVPWM — **7,16×10⁻⁷ duty**;
- полный ADC sweep: отличие тока <**7,7 мкА**, напряжения <**27 мкВ**,
  температуры <**0,0008 °C**; PWM compare отличается не более чем на один отсчёт;
- Hall monitor, Hall handoff, motor alignment, ADC scaling и control integration
  для обоих профилей. Control integration: 70 float / 85 numeric-fixed проверок;
- Cortex-M0 compile-only ядер PLL/Hall/FOC/ADC/NTC/PWM — без FP helper-функций;
- `make -C libecu test-compile NUMERIC_PROFILE=float` и `...=fixed`;
- Release ARM, включая отдельную fixed-сборку с физической ручкой газа.

`utility/check_numeric_path.py` обходит прямые вызовы из периодических функций,
native OSC/ручки и конкретных виртуальных STM32-реализаций. В проверенных
native-путях нет арифметических VFP-инструкций или software FP helpers.
Это аудит выбранных путей, а не всего ELF и не измерение скорости Cortex-M0.

Старый `tests/test_motor_pll/run.sh` сохраняет исходное падение S1:
на 0,1 с PLL=13,184695 при реальной скорости 40,040726. S2–S4 проходят;
условие S1 не изменялось. Подробности исходного дефекта — в
[первом отчёте](NUMERIC_PROFILES_PROGRESS.md#исходное-падение-pll).

## Сравнение на моторе

Те же CPID=0,15/200, SPID=0,01/0,05, PLL=100/5000, ACC=20.
Для FOC на **этом** инверсном моторе на стенде заданы `FANG=120`,
`FPID=1.56,2080`. Это экспериментальные runtime-настройки, не идентифицированная
R/L-модель JK42BLS01. Пресеты в `motor_config.hpp`, включая MOTOR_1, сохранены.

Средняя скорость в FORWARD, окно 3 с после 2 с установления:

| Алгоритм | Задание | float | fixed |
|---|---:|---:|---:|
| Six-step | 2 | 1,985 | 2,024 |
| Six-step | 5 | 4,998 | 4,986 |
| Six-step | 10 | 9,974 | 10,007 |
| Six-step | 20 | 20,007 | 20,014 |
| FOC | 2 | 1,980 | 2,169 |
| FOC | 5 | 5,016 | 5,034 |
| FOC | 10 | 10,034 | 9,955 |

Проверены REVERSE и снижение задания до нуля для обоих алгоритмов/профилей.
Ошибок Hall в финальных сериях нет. На 2 об/с токовый режим остаётся неравномерным:
у FOC σ=1,070 float / 1,408 fixed об/с в этих окнах. Малоскоростная настройка
лёгкого ненагруженного ротора остаётся отдельной работой; таблица не доказывает
равенства механических переходных процессов двух независимых прогонов.

Ступени six-step 0,15 ↔ 0,40 А, по 10 переходов:

| Показатель | float | fixed |
|---|---:|---:|
| Медиана установления вверх / вниз | 1,85 / 1,55 мс | 1,85 / 2,05 мс |
| RMS ошибки после первых 5 мс | 27,07 мА | 29,50 мА |
| P95 абсолютной ошибки | 47 мА | 47 мА |
| Наибольший измеренный выброс | 84,2 мА | 212,2 мА |

Отсчёты коммутации включены. OSC пакует мА с усечением, поэтому fixed-задания
этих записей представлены как 149/399 мА (ошибка квантования упаковки до 1 мА).
Ступени сняты до исправления compiler barriers в изолированном DWT benchmark;
их отдельные бинарники и SHA сохранены, управляющий код тот же.

### Время

По 20 000 callback/IRQ samples на серию, OSC включён. Ниже финальные FORWARD
окна: six-step при 20 об/с, FOC при 10 об/с.

| Режим | Callback среднее / максимум, мкс | IRQ с HAL среднее / максимум, мкс |
|---|---:|---:|
| float six-step | 15,25 / 21,04 | 17,20 / 23,09 |
| fixed six-step | 24,37 / 32,42 | 26,27 / 34,45 |
| float FOC | 17,34 / 20,60 | 19,27 / 22,74 |
| fixed FOC | 39,80 / 42,74 | 41,72 / 44,79 |

Во всех восьми финальных сериях превышений 50 мкс нет. IRQ-замер включает HAL
и callback, но не аппаратный exception entry/exit и завершающую запись самого
профайлера. У fixed FOC запас небольшой; в предварительной сборке наблюдалось
47,97 мкс с HAL. Это наблюдавшиеся значения, не доказанная верхняя граница WCET.

При отключённом мосте отдельный синтетический тест ядра FOC измерил максимум
**6,11 мкс float / 25,52 мкс fixed** на ветви насыщения. Он не включает ADC,
Hall, PWM и HAL. Полный IRQ при длительном насыщении FOC ещё требует проверки.
Внутри benchmark стоят compiler barriers на вход и результат: одного volatile
чтения DWT недостаточно, чтобы компилятор оставил чистые ADC-вычисления между замерами.

Финальные bench ELF, включая OSC и DWT fixtures:

| float | 73 016 | 520 | 16 368 |

Оба укладываются в 128 КБ Flash / 32 КБ RAM. `.su`-кадры: callback 16 байт,

## Воспроизведение

```bash
./build.sh --numeric-profile fixed
make -C libecu test-compile NUMERIC_PROFILE=fixed

cmake -S STM32G431 -B STM32G431/build-control-fixed \
  -DCMAKE_BUILD_TYPE=Release -DNUMERIC_PROFILE=fixed \
  -DPI_NUMERIC_PROFILE=float -DENABLE_THROTTLE_BRAKE_CONTROL=OFF \
  -DENABLE_BENCH_PROFILING=ON
cmake --build STM32G431/build-control-fixed -j4
python3 utility/check_numeric_path.py STM32G431/build-control-fixed/open-ecu.elf
```

Для float заменить имя build-каталога и `NUMERIC_PROFILE`. Версии:
`1.1.0-control-float` / `1.1.0-control-fixed`. Legacy PI-only override остаётся
доступным через `NUMERIC_PROFILE=float, PI_NUMERIC_PROFILE=fixed`.

После прошивки соответствующего ELF:

```bash
python3 utility/bench_motor.py --poles 8 --algo 1 --mode speed \
  --values 2 5 10 --set FANG=120 --set FPID=1.56,2080 --set ACC=20 \
  --seconds 3 --settle 2 --osc --out /tmp/opencode/foc-check.json
```

Для замера передать bench-скрипту `--profile-address` со значением символа
`pwm_bench_profile` **из прошитого ELF**, затем прочитать счётчики:

```bash
arm-none-eabi-nm STM32G431/build-control-fixed/open-ecu.elf | grep pwm_bench_profile
python3 utility/profile_numeric.py --elf STM32G431/build-control-fixed/open-ecu.elf \
  --out /tmp/opencode/foc-timing.json
```

`profile_numeric.py --sample 20000` самостоятельно запускает замер в текущем
состоянии привода; без `--sample` только читает завершённый capture.
